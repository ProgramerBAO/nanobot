# Nanobot Cube 报表产品

> 使用者上手教程见 [USER_GUIDE.md](USER_GUIDE.md)（公司内部分发入口）；
> 本文件是产品能力与数据口径的权威定义。

## 产品定位

Nanobot 是面向内部 SRE、运营和管理人员的只读 Cube 报表与管理查询入口。固定报表使用确定性 `ReportRunner`，灵活管理问题使用 `magik-cube-admin` Skill。Grafana、企业微信和钉钉当前只保留扩展能力，不属于已启用产品范围。

## 使用场景

- `日报`、`周报`、`月报`：默认生成只含核心 KPI 的简报。
- `详细日报`、`详细周报`：生成保留排行、分段和下钻的矩阵报表。
- `完整日报`：生成兼容的完整文本报表。
- `tencent_token_hub 有哪些 Endpoint`：通过只读 Admin API 查询真实管理对象。
- 新建订阅默认保存简报模板；已有订阅和历史报表继续使用原 `template_id`。
- 简报标题按已验证的客户别名和模型范围生成；单模型显示模型名，多模型显示“全部模型”。
- 所有用量简报不显示时间桶、桶数量或 interval；详细分析和健康诊断仍保留必要的趋势口径。
- 用量简报结果不提供订阅按钮；已有订阅继续执行。新建订阅可使用受控自然语言、引用已生成的报表卡片，或进入 WebUI `Report platform`。
- “我的订阅”按订阅编号逐条展示报表类型、状态、发送计划、统计范围、数据周期
  和口径版本；每条启用/停用按钮紧邻对应订阅，操作后返回刷新后的订阅卡片。
- `Report platform` 的订阅管理使用引导式表单：管理员选择报表、客户、模型、周期、频率、时间、时区和接收会话即可完成创建或编辑；界面不要求填写 Cron 或 `report_params_json`。
- 报表类型策略把“是否允许新订阅”和“结果卡片是否显示订阅按钮”分开管理。`show_subscription_button=false` 只隐藏按钮，不影响自然语言、引用报表或订阅中心；`subscription_mode=disabled` 才阻止新建订阅。

## 统计与交互契约

日报查询日期为 `D` 时，环比固定使用 `D-1`，同比固定使用 `D-7`。多客户日报每个客户/模型行同时显示当前周期 Token 总数，变化只显示百分比。多客户周报使用上一完整自然周对比此前一完整自然周，仅显示环比。独立对比周期区块不在简报中渲染，但基准日期保留在底部说明、运行记录和 `ReportContext`。

平均 TPM 只使用 Cube `analysis/endpoint-max-tpm/daily/query` 的 `avgTpm`，不得跨客户或 Endpoint 聚合。接口失败、缺失和成功空数据必须保持不同状态，不得转换为 0。

小时 TPM 报表只使用目标上一完整小时的 point：峰值取 `maxTpm`，均值取 `avgTpm`。请求必须携带 `time_level=TIME_LEVEL_HOUR`（小时粒度开关）且 `endDate` 为目标小时所在日的次日（同日范围只返回 00 点），再由本地过滤只保留目标小时；未流逝小时返回 0 占位并不得进入报表。接口未返回目标小时数据时，峰值/均值均显示“暂不可用”，不得使用其他小时或推算。机器为双来源双列：占用来自 `analysis/model-machine-usage/query`（发送时当前配置快照），使用中机器来自 `analysis/machine-tpm-trend/query`（上一完整小时时点值），均按唯一模型查询一次、跨集群求和、平台级且不得复制为客户独占资源，卡片以“机器占用”与第二机器列分别展示。**冗余算力分析（2026-10-10，开关 `hourly_tpm_capacity_analysis` 默认开启，页面关闭即时回退“机器真实使用”旧列且不发 30 天查询）**：第二机器列为“机器冗余”= 占用 − ⌈当前小时负载 ÷ 30 天最佳单机吞吐⌉，token 均值口径（`tpmPerMachine` = `totalTokens` ÷ 机器数 ÷ 60，machine-tpm-trend 自带，30 天 HOUR 窗口每组 720 点完整返回），按 集群×卡型 分组计算后求和（两接口 gpuProduct 连字符/空格拼写差异经归一化 join，trend 拼通用于显示）；闲N = 占用−使用中，是冗余中整小时零使用的子集（零使用原因接口无法区分），使用中机器数可由 占用−闲 推出；冗余含“在用但欠载”机器，副标题汇总“冗余 N 台（闲 M 台）”。30 天基线每模型每日缓存一次（`report_settings`，刷新失败沿用旧值并标注基准日期）；基准 <7 天不出数（—），需求>占用记 0；基线/小时 token 查询失败均为信息性告警不降级质量（实证单模型可能全窗口 500）。多客户模型追加折算表：按各客户目标小时 `active-tenant-daily-usage` TIME_LEVEL_HOUR 的 token 占比分摊模型级冗余（估算值，仅多客户模型发起 token 查询；占比只用 token，永不用 avgTpm 跨界聚合），token 数据未出的模型不折算并在折叠区点名。占用缺失降级 `partial`（占用列“暂不可用”、冗余列 —），使用缺失为信息性告警。多 Endpoint 模型的均值不得跨 Endpoint 汇总，均值列显示“多 Endpoint，不汇总”并提供 Endpoint 明细表（拆为第 2 张卡）。

集群机器库存来自 `analysis/machine-usage-summary/query`（POST `{"noloading":true}`，发送时平台级快照，`occupiedMachineCount` 语义为测试机总数）：七列表格（集群 | 机器总数 | 空闲 | 生产 | 测试 | 开发 | 备用，user-confirmed 2026-09-17 空闲紧随总数）按集群名排序，生产 = 机器总数 − 测试 − 开发 − 备用 − 空闲（计算列，分项缺失或之和超过总数时显示 —，后者同时产生信息性告警）。**机器总数为 0 的集群不进表，并在折叠区标注"机器总数为 0 的集群已隐藏（N 个）"（2026-09-17，不静默丢失）；总数缺失（—）行为不变。**整表为信息性补充：接口失败或空列表不产出该表、不降级质量；集群级空闲与模型级（闲N）/副标题机器空闲口径不同、互不换算。纯文本 fallback 以单行"集群空闲机器"摘要呈现（缺失空闲数的集群不入行）。

数量单位（2026-09-17）：Token、TPM、请求数等**量值统一使用 K/M/B 阶梯**（1K=1,000、1M=100 万、1B=10 亿），至多 2 位小数去尾零（1000→1K、6683 万→66.83M、1 亿→100M、110.92 亿→11.09B、713.01 亿→71.3B）；机器数/样本数保持整数，百分比、毫秒延迟、金额不变。多客户日/周报简报、小时 TPM、legacy 日报、声明式简报全部经共享 `format_quantity_compact`（`nanobot/utils/number_format.py`）单源。

涨跌标记（2026-09-17）：同比/环比 |变化%| ≥ 阈值时在变化旁追加 📈（涨）/📉（跌），两个方向都标；新增/无变化/无基准不标。阈值默认 30%，Report platform 订阅管理页输入框可改（5-95 整数，保存即生效、无需重启），"恢复默认"删覆盖；非法或越界覆盖值回落默认。

小时播报的指定小时：`hours` 为 0-23 的小时列表（去重排序、1-24 个），编译为 `5 9,10 * * *`；`"每小时"`保持全 24 小时（`5 * * * *`）。执行窗口始终由运行时钟推导上一完整小时，与 cron 表达式无关。`hours` 仅对小时 TPM 报表有效（recent1h 与 hourly 双向绑定，其他组合拒绝）；工作日/每周/每月与小时列表的组合不支持（确定性解析放弃、不做静默周末投递）。快照反推：分钟 5 + 小时列表（≥2）或小时 TPM 模板上下文中的单小时判定为 hourly，避免编辑时退化为每天 HH:05。订阅意图的投递动词词表含单字"报"（2026-09-17）——"…23点报上一小时TPM"这类措辞与"播报/发送/推送"同等进入订阅链路；无时钟的普通查询（如"每天查看日报"）只触发一次有界分类调用，不会被静默转成订阅。

全部模型报表执行前的活跃模型发现：某客户窗口内无活跃（有用量）模型属于**成功空数据状态，不是失败**（2026-09-17）——部分客户无用量时照常出报表，并在卡内显式列出无用量客户（不静默丢失）；全部客户无用量时投递轻量提醒卡（列出无用量客户与窗口，quality=complete，不记 error 投递、不触发瞬时重试，运行记录留一条 ok），模型有用量后自动恢复完整报表。目录查询失败（权限/上游）仍按失败处理，文案不变。

投递组（2026-09-16）：组 = 指纹身份去掉 chat 目标（channel/user/template/schedule/timezone/params 相同）跨不同 chat 的 N 行，读取时派生、无组列。每行独立 Cron/指纹/`{subscription_id}:{scheduled_at_ms}:{version}` 幂等——投递、重试、部分失败互不影响；已知取舍：N 个目标 = 每个触发时点 N 次只读数据查询；组编辑逐行 CAS、非原子（中途失败保留已应用行并报错指认失败行）。目标数上限 20；同目标重复（409）按目标跳过并汇总，不整体失败。聊天创建仍为单目标；跨会话重复创建本身已放行（指纹含 chat_id，此前"被拦截"为收敛前旧版行为）。

灵活管理查询先 `search`，再 `describe`，最后 `call`。多步查询先取得父实体真实 ID；写接口、用户提供的 URL/API 路径和敏感字段始终阻断。
