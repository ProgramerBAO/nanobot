# Nanobot Cube 报表产品

## 产品定位

Nanobot 是面向内部 SRE、运营和管理人员的只读 Cube 报表与管理查询入口。固定报表使用确定性 `ReportRunner`，灵活管理问题使用 `magik-cube-admin` Skill。Grafana、企业微信和钉钉当前只保留扩展能力，不属于已启用产品范围。

## 使用场景

- `日报`、`周报`、`月报`：默认生成只含核心 KPI 的简报。
- `详细日报`、`详细周报`：生成保留排行、分段和下钻的矩阵报表。
- `完整日报`：生成兼容的完整文本报表。
- `tencent_token_hub 有哪些 Endpoint`：通过只读 Admin API 查询真实管理对象。
- 新建订阅默认保存简报模板；已有订阅和历史报表继续使用原 `template_id`。
- 简报标题按已验证的客户别名和模型范围生成；单模型显示模型名，多模型显示“全部模型”。
- 所有用量简报不显示时间桶、桶数量或 interval；详细分析和健康诊断仍保留必要的趋势口径。
- 用量简报结果不提供订阅按钮；已有订阅继续执行。新建订阅可使用受控自然语言、引用已生成的报表卡片，或进入 WebUI `Report platform`。
- “我的订阅”按订阅编号逐条展示报表类型、状态、发送计划、统计范围、数据周期
  和口径版本；每条启用/停用按钮紧邻对应订阅，操作后返回刷新后的订阅卡片。
- `Report platform` 的订阅管理使用引导式表单：管理员选择报表、客户、模型、周期、频率、时间、时区和接收会话即可完成创建或编辑；界面不要求填写 Cron 或 `report_params_json`。
- 报表类型策略把“是否允许新订阅”和“结果卡片是否显示订阅按钮”分开管理。`show_subscription_button=false` 只隐藏按钮，不影响自然语言、引用报表或订阅中心；`subscription_mode=disabled` 才阻止新建订阅。

## 已实现功能

| 能力 | 当前行为 | 权限与开关 |
| --- | --- | --- |
| 用量简报 | 日报、周报、月报、区间报表；Token、请求数、平均 TPM、最高 Endpoint 峰值 TPM | `cube_usage_brief_template` |
| 简报默认路由 | 普通周期问法进入简报；详细和完整问法保留旧模板 | `cube_usage_brief_default` |
| Cube 灵活查询 | 租户、模型、Endpoint、账单、集群、日志和配置的只读查询 | `cube_admin_skill_help`，且 Admin Tool 已启用 |
| 进一步分析 | 简报卡片携带原客户、模型和时间窗口进入矩阵报表 | 服务端重新执行权限校验 |
| 多客户多模型日报简报 | 按客户分组展示模型 Token 的同比和环比；手工多选最多 20 个模型，“全部模型”受 200 个客户/模型组合上限保护 | `cube_multi_scope_brief`，默认关闭 |
| 单机折算 TPM 峰值 | 按模型、集群、卡型展示小时折算 TPM 峰值；不代表具体机器 | `cube_machine_tpm_report`，默认关闭 |
| Report platform | 管理模板启用/订阅策略、订阅计划和订阅授权，并记录管理审计 | `report_management_v1`，默认关闭；WebUI 管理 token |
| 自然语言与引用订阅 | 结构化 LLM 只提取客户别名、模型范围和发送计划；服务端解析真实 ID、重做 RBAC 并展示确认卡 | `cube_subscription_nlu_v2`、`cube_report_reference_subscription` |
| 多客户自然语言订阅 | 从原文提取并与实时 Cube 客户目录合并，保留全部客户和“全部模型”语义；确认前不创建任务 | `cube_subscription_nlu_v2`；V3 增强解析默认关闭 |
| 引用报表创建订阅 | 同群报表卡片通过服务端 `message_id` 引用恢复已验证范围，历史日期不进入周期订阅 | `cube_report_reference_subscription` |

区间和近 7 天的进一步分析使用独立 `usage_custom_matrix`，标题与基准均按“区间 / 前一等长周期”展示，不借用周报名称。

## 统计与交互契约

日报查询日期为 `D` 时，环比固定使用 `D-1`，同比固定使用 `D-7`。KPI 按“同比、环比”顺序展示，变化只显示百分比；独立对比周期区块不在简报中渲染，但基准日期保留在底部说明、运行记录和 `ReportContext`。

平均 TPM 只使用 Cube `analysis/endpoint-max-tpm/daily/query` 的 `avgTpm`，不得跨客户或 Endpoint 聚合。接口失败、缺失和成功空数据必须保持不同状态，不得转换为 0。

灵活管理查询先 `search`，再 `describe`，最后 `call`。多步查询先取得父实体真实 ID；写接口、用户提供的 URL/API 路径和敏感字段始终阻断。

## 验收

- `tencent_token_hub Kimi-K3 2026-08-31日的日报` 返回简报，并显示同比、环比。
- `详细日报` 和“进一步分析”进入矩阵报表；`完整日报` 保留完整文本输出。
- 简报不包含独立对比区块、分段、排行、关键变化或详细样本表。
- 多客户多模型简报按客户分组，固定显示 `同比=D-7`、`环比=D-1`；失败项不得折叠为无用量。
- 多客户简报选择“全部模型”时，系统先从 Cube 实时模型目录展开每个客户的模型，再按明确的客户/模型组合查询；目录为空或失败时直接提示，不生成 `0 个模型` 的空壳报表。
- “全部模型”简报自动隐藏当前日、前一日和上周同期均无 Token 用量的模型；任一基准期有用量、用户明确点选或接口查询失败的模型仍然展示。
- 多客户多模型简报把统计窗口、同比/环比基准、时区、来源、口径、隐藏模型数量和质量原因统一放入默认关闭的“报表说明与数据质量”折叠区。成功但无用量的目录模型不再导致报表标记为 `partial`；真实查询失败仍在质量状态和折叠详情中明确展示。
- `Kimi-K3 单机 TPM 峰值` 显示集群、卡型、峰值北京时间、机器数、GPU 数和样本质量。
- `tencent_token_hub 有哪些 Endpoint` 使用真实只读 Admin API 结果回答。
- Feishu、WebUI、Markdown 和文本 fallback 保持相同统计语义。
- 用量简报在 Feishu、WebUI、Markdown 与文本 fallback 中均不显示时间桶或结果订阅按钮。
- 多条订阅的编号、状态与启停按钮在 Feishu 和 WebUI 中一一对应。
- `每天上午十点发送阳春面、豆汁、佛跳墙全部模型的多客户日报简报` 必须在确认卡中保留三个客户，并创建 `usage_customer_model_daily_brief`。
- 引用日报卡片回复 `工作日上午十点发送给我` 时继承模板、客户和模型范围，但不继承历史查询日期；旧卡片、跨群引用和过期引用必须失败关闭。
- “全部模型”订阅在每次执行前读取各客户的实时模型目录，新模型自动进入报表，持续无用量模型沿用现有隐藏规则。
- Report platform 的模板策略使用 revision 防止并发覆盖，订阅操作与 Cron 状态同步。
- Report platform 只允许 Gateway/WebUI 管理 token 操作策略和订阅；旧兼容接口保留，但新建和编辑优先使用引导式表单。测试账号的订阅接收人固定为当前用户，未经单独授权不会扩大发送范围。

## 非功能与运维

所有 Cube 调用必须只读、有 timeout、受控重试和输出脱敏。发布时先注册模板，再对白名单开启默认路由；观察报表成功率、`partial/missing` 比例、执行 P95 和投递失败率。

回滚可分别关闭 `cube_multi_scope_brief`、`cube_machine_tpm_report` 和 `report_management_v1`。策略表与审计表保留但不参与执行，旧简报、已有订阅和历史记录不删除；不涉及 Cube 远端写入。
